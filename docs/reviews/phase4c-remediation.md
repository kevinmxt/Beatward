# Beatward Phase 4C 修正与验收清单

本清单面向 Phase 4D，不要求扩大 Phase 4C 的产品范围。优先处理影响长期运行边界的事项。

## P2-1 通知限频器键容量

- [ ] 明确键容量策略：达到上限时拒绝新键，或采用可证明有界且不会驱逐活跃窗口的策略。
- [ ] 将清理触发条件调整为容量边界明确的逻辑。
- [ ] 为过期窗口、活跃窗口、渠道删除和容量耗尽增加单元测试。
- [ ] 暴露当前键数量/容量耗尽计数，避免静默退化。

**验收：** Map/缓存键数始终不超过配置上限；容量耗尽时行为可预测；不能通过反复创建新渠道绕过单用户每分钟/每小时限频。

## P2-2 账号禁用与在途任务

- [ ] 产品语义明确为“阻止新任务”还是“尽可能中止在途任务”。
- [ ] 覆盖 Probe 执行期间禁用、Heartbeat timeout 事务期间禁用、Notification 发送前禁用。
- [ ] 如要求严格互斥，设计账号状态与任务提交/发送的共同锁或版本门禁，检查锁顺序与死锁风险。
- [ ] 对已经发出的外部通知说明不可撤回的边界。

**验收：** 并发测试与文档语义一致；禁用后不会持续启动新的探测/心跳扫描/通知投递。

## P3-1 管理审计补齐（对应 4D）

- [ ] 记录通知渠道创建、更新、启用/禁用、删除。
- [ ] 记录登录失败、登录限流和账号禁用拒绝事件。
- [ ] 统一 actor、target、event、result、traceId、timestamp 字段。
- [ ] 确保日志不包含密码、邀请码、重置码、PushPlus token、息知 Key、邮箱 SMTP 密码或完整渠道配置。
- [ ] 验证日志轮转、权限和保留策略。

**验收：** 关键操作可按用户/时间/traceId 追溯；敏感值脱敏测试通过。
